The style contract

This is how VinUI stays consistent across styles. Every component follows these rules in every style. A style can only change the right-hand column.

🔒 Never changes between styles

Your code and layout are safe when you switch.

  • Component names, props and HTML class names
  • HTML structure (anatomy) of each component
  • Variant list: primary, secondary, outline, ghost, danger
  • Size scale: 30 / 36 / 44 px heights, 4 px spacing grid
  • Keyboard behaviour, ARIA roles and focus handling
  • Token names (--vin-radius, --vin-primary, …)
  • Light and dark mode support

🎨 Each style decides

Set through token values plus a few documented overrides.

  • Colour palette and gradients
  • Corner radius (0 to 16 px)
  • Border width and colour
  • Shadow type: subtle, glow, hard offset, neumorphic, bevel
  • Font family, weight and letter case
  • Surface treatment: solid, blur, texture
  • Motion: easing and hover/press feel

One component, three token files

styles/glass.css (excerpt)
[data-vin-style="glass"] {
  --vin-radius: 14px;
  --vin-bw: 1px;
  --vin-surface: rgb(255 255 255 / .55);
  --vin-primary-bg: linear-gradient(135deg, #8b5cf6, #ec4899);
  --vin-shadow: 0 4px 14px -4px rgb(124 58 237 / .35);
  --vin-blur: 18px;
}
/* button.css reads the tokens and is shared by every style */
.vin-btn { border-radius: var(--vin-radius); background: var(--vin-primary-bg); }

Quality checks every component must pass, in every style

  • Visual snapshot test in each style × light/dark (3 × 2 = 6 screenshots per component)
  • Automated accessibility check (axe) and contrast check per style
  • Same props test across HTML, React, Vue and Svelte
  • No style may add or remove a prop, slot or HTML element
