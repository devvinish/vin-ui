VinUI: one component library, eight styles, any framework

A free, open-source component library on vinish.dev. Developers pick a style and an accent colour, then copy or install accessible components for HTML, React, Vue or Svelte. The code lands in their own project, and they own it.

Licence MIT Repo public URL vinish.dev/ui npm @vinish/ui Price free

01Summary

Most component libraries offer one visual style. You either like that look or you spend days restyling it. VinUI's answer is one set of components drawn in eight complete styles. Every style is finished down to shape, borders, shadows, type and motion, not only colour.

A developer chooses a style and accent in the sticky header. From that moment, everything on the site follows that choice: the previews, the code samples, the CLI command and what the AI tools return. The choice is saved in their browser and can be exported as a small theme file.

Everything is built from a single public GitHub repository. Each release produces the website, the downloadable code, the CLI on npm, the MCP server for AI tools and an llms.txt file. Hosting is static on Cloudflare Pages, so the running cost stays close to zero.

The default style for first-time visitors is Precision, because it suits the widest range of projects. The working prototype of all eight is in the Style Lab (prototype/style-lab/).

04The style contract

How eight styles stay as consistent as a single-style library.

Never changes between styles

  • Component names, props and class names
  • HTML structure (anatomy) of every component
  • Variants: primary, secondary, outline, ghost, danger
  • Size scale: 30 / 36 / 44 px controls, 4 px spacing grid
  • Keyboard behaviour, ARIA roles and focus handling
  • Token names, e.g. --vin-radius, --vin-accent
  • Light and dark support

Each style decides

  • Colour palette and surfaces
  • Corner radius
  • Border width and line type
  • Shadow type: hairline, soft light, inflated, none
  • Font family, weight and letter case
  • Texture (Paper's dots, Terminal's dashes)
  • Motion: easing and press feel

Technically, each style is one CSS file of token values plus a short list of documented per-component tweaks. Components read only the tokens, so switching styles means changing one attribute:

<html data-vin-style="tactile" style="--vin-accent: #0d9488">

Because a developer's markup never changes, they can switch styles later without rewriting anything.

09CLI: how npx @vinish/ui works

npx comes with Node.js. It downloads our small CLI from npm, runs it once and leaves nothing installed. The CLI downloads a component's registry file from vinish.dev and writes that code into the developer's project.

Developer runs npx @vinish/ui initIt detects the framework and asks for style, accent and folder (or reads --theme vin-theme.json), then writes vin.json and vin.css.
Developer runs npx @vinish/ui add button dialogThe CLI reads vin.json and fetches vinish.dev/ui/r/react/button.json.
Files are written into their projectsrc/components/vin/button.tsx, plus any small dependency installed automatically.
They own the codeNo runtime dependency on our servers. They can edit anything.
vin.json (created by init) 
{ "framework": "react", "style": "tactile", "accent": "#0d9488", "path": "src/components/vin" }
Commands
CommandDoes
initSet up a project: framework, style, accent, folder
add <names…>Add components
style <name>Switch the project's style (rewrites vin.css only)
diff <name>Show what changed upstream since you added a component
listList the available components
mcpStart the MCP server for AI tools

Plain HTML users don't need the CLI. One line is enough: <link rel="stylesheet" href="https://vinish.dev/ui/v1/tactile.css">, then copy the HTML from the docs.

10MCP and AI tools

MCP (Model Context Protocol) lets AI coding tools such as Claude Code, Cursor, VS Code Copilot and Windsurf call outside tools. Our MCP server gives the AI the real, current VinUI code in the developer's own style and framework, so it doesn't have to guess.

What the developer adds to their AI tool's settings 
{
  "mcpServers": {
    "vin-ui": { "command": "npx", "args": ["-y", "@vinish/ui", "mcp"] }
  }
}
MCP toolWhat the AI can do
list_componentsSee every component and category
search_componentsFind the right one ("modal" leads to Dialog)
get_componentGet the code for their framework and style, with props and examples
list_stylesSee the 8 styles and what each looks like
get_themeRead the project's vin.json settings
add_componentWrite the files, the same as the CLI (the AI tool asks the user first)
OptionHowCostWhen
LocalRuns on the developer's computer via npxFree, nothing for us to hostLaunch
RemoteCloudflare Worker at vinish.dev/ui/mcp; developers paste a URLCovered by Cloudflare's free plan for normal trafficLater, if requested

llms.txt sits alongside it: one plain-text file listing every component with a short description and a docs link. Any AI that reads web pages can use it, even without MCP. It is generated on every build.

11Hosting and releases

Every change

Work on a branch, open a pull requestYour own changes or a community contribution
GitHub Actions run the checksLint, types, accessibility (axe), screenshots of every component in 8 styles × light/dark
Cloudflare Pages builds a preview linkSee the change live before it is merged
Merge to mainThe website deploys automatically

Every release

Tag a version, e.g. v1.2.0Changelog generated with Changesets
GitHub Action publishes to npmWith provenance, so people can verify the package came from our repo
Versioned CSS goes live/ui/v1/… stays stable, so HTML users don't get surprise changes

Serving at vinish.dev/ui

The library site is its own Cloudflare Pages project. A small Cloudflare Worker route sends vinish.dev/ui/* to it, so the main site and the library deploy independently but share one domain. If the main vinish.dev site is also on Cloudflare Pages, this is a few lines of config.

Secrets (the npm publish token, Cloudflare API token, any analytics keys) live only in GitHub and Cloudflare secret settings, never in the repository. main is protected: only you can merge, and every pull request must pass the checks.

Supported browsersLatest two versions of Chrome, Edge, Firefox and Safari (iOS included)
Accent contrast: a very light accent (e.g. yellow) can be hard to read on a light background. The theme engine automatically adjusts the accent shade used for text and outlines, while keeping the exact colour for fills.

15Risks and open questions

RiskLevelWhat we do about it
Keeping 8 styles consistent as components growhighToken-only styles, the style contract, and automated screenshot tests. Budget about 20–30% extra time per component.
Complex components (Table, Date picker) in Terminal, Paper and EditorialmediumDesign those three first for each complex component; they are the hardest.
npm name @vinish not availablemediumCheck now; fallbacks are @vinishdev/ui or vin-ui-kit.
